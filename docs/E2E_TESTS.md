# End-to-end test suite reference

This is the canonical list of project-specific end-to-end test scripts.
Each entry shows the script and a verbatim description of what it
exercises. Run them from the repo root; most are gated on
`E2E_API_BASE_URL` (e.g. `http://localhost:80`) so they drive the live
api-server + test-builder workflows behind the shared proxy.

For the day-to-day "did anything break?" gate, see
`scripts/check-role-permission-tests.sh` at the bottom.

## Scanners / static checks

- `pnpm --filter @workspace/scripts run check-duplicate-test-classes`: Fail-fast scan of `memento-ux-tests/**/*.cs` for C# build-killers — duplicate type names (CS0101), duplicate `[Test]`/`[TestCase]` method names within a fixture (CS0111), and classes marked both `abstract` and `sealed` (CS0418). Also runs as an MSBuild `BeforeBuild` target on the UX test project and as part of the root `pnpm run build`.
- `pnpm --filter @workspace/scripts run test:check-csharp-build-killers`: Synthetic regression tests covering each scanner check (clean fixture, duplicate type, duplicate `[Test]`, stacked `[TestCase]`, abstract-sealed, sealed-abstract).
- `pnpm --filter @workspace/scripts run check-db-drift`: Compares the live Postgres database against the Drizzle schema and exits non-zero on drift, listing missing/extra tables and columns. Skips with a clear message when `DATABASE_URL` is unset. Wired into `pnpm run build`. When drift is reported, run `pnpm --filter @workspace/db run push`.

- `pnpm --filter @workspace/test-builder run test:e2e:delete-approval`: End-to-end Playwright spec for task #42 (admin approval to delete a project). Covers limited_admin→pending, admin approve removes files, admin reject keeps files, and the sole-admin `acknowledgeIrreversible` path. Gated on `E2E_API_BASE_URL` (e.g. `http://localhost:80`).
- `pnpm --filter @workspace/test-builder run test:e2e:clone-project`: End-to-end Playwright spec for `POST /api/projects/clone`. Spins up a bare local repo with `git init --bare` and a `.testbuilder.json` marker, then exercises three paths against the live workflows (gated on `E2E_API_BASE_URL`, requires `APP_ENVIRONMENT=development` so `file://` URLs pass repo URL validation): inline-PAT happy path, the `existing_pat` branch (clone uses a Repos PAT row and the resulting git-config reports `repoPatId` / `repoPatName` / linked `patLastFour`, plus the `409` bound-PAT delete guard), and the marker-rollback path (a clone with no recognizable project file returns `400` and leaves no orphan project on disk).

- `pnpm --filter @workspace/test-builder run test:e2e:fork-and-branches`: End-to-end Playwright spec for task #58 (personal forks + branch dropdown). Drives the live api-server + test-builder workflows behind the shared proxy. API assertions: (a) my-fork PUT redacts the PAT (only `patLastFour` leaks; plaintext never appears in the response body), (b) cross-user isolation — a second admin signed in via dev-login sees an unconfigured fork for the same project, (c) DELETE clears the row and is idempotent (204 on the second call), (d) the branches API returns `hasGitWorkingCopy:false` for a project without a `.git` working copy and surfaces invalid branch names as structured `{ok:false, errorCode}` HTTP 200 responses (never thrown). UI assertions: (e) the branch dropdown in the Explorer panel is hidden when the project has no git working copy, (f) Settings → Git Repos save-fork flow renders only the redacted PAT (the plaintext never appears in the DOM after save), (g) the Workbench branch dropdown can create + switch to a new branch via the inline prompt and switch back to main, (h) with a personal fork configured, the toolbar's **Push** action (a real UI click, observed via `page.waitForRequest`) pushes the working-copy change to the **fork bare on the new branch** — never on the upstream bare and never on main, and (i) the dialog's **Clear fork** button reverts the section to the unconfigured shape and `GET /my-fork` returns `configured:false`. Set `E2E_API_BASE_URL` (e.g. `http://localhost:80`).

## Selector heal (Fix selector dialog)

- `pnpm --filter @workspace/test-builder run test:e2e:fix-selector`: End-to-end Playwright spec for the AI Fix Selector recovery flow (task #15). Drives the real `<FixSelectorDialog />` on a standalone fixture page (`e2e-fix-selector-fixture.html` + `src/e2e-fix-selector-fixture.tsx`) so the spec is hermetic — it does NOT require the live api-server or a real project. The four heal endpoints (`/api/selectors/heal/ai-available`, `/api/selectors/heal/ai-suggest`, and `/api/selectors/heal` for both the dry-run preview and the real apply) are mocked via `page.route()`. Asserts the happy path: (a) the AI availability probe enables the call-to-action, (b) `Suggest a fix with AI` POSTs the failing-step context (`oldSelector`, `actionDescription`, `pageUrl`, ...) and renders the suggestion card with `ai-confidence` / `ai-explanation` / `input-ai-edited`, (c) `Preview replacement` POSTs `dryRun:true` and shows the per-recording + per-Selectors-file diff lists, (d) ticking `checkbox-ack-heal` unlocks `button-ai-apply`, (e) the real apply POST forwards `via:"ai"` plus the full AI provenance (`aiProvider`, `aiModel`, `aiConfidence`, `aiTokensIn`, `aiTokensOut`) for the `selector_heal` audit row and (f) `onApplied` increments the fixture counter — proof the dialog transitioned cleanly to the post-apply state. A second test covers the no-key empty-state branch: when the availability probe says `available:false` the AI tab renders `fix-selector-ai-no-key` with a working setup link, the suggest endpoint is never called, and the manual `Edit text` tab still works.

Drives the live api-server + test-builder workflows behind the shared proxy (gated on `E2E_API_BASE_URL`, e.g. `http://localhost:80`, with `APP_ENVIRONMENT=development` so dev-login is enabled). Parameterized over all four supported languages (C# / Python / Node.js / Java) the happy path: (a) opens the URL dialog from the toolbar's Actions menu and submits a URL, (b) asserts the toolbar swaps into pre-attach mode (`button-start-recording-attach` + `button-close-open-browser` visible) and that `button-test-with-ai` is disabled with the tooltip `Close the open browser session first.`, (c) opens the attach-mode Start Recording dialog and asserts the Base URL block (`section-base-url`) and Browser size block (`section-browser-size`) are hidden, (d) attaches to a seeded existing test class via `select-existing-class` + `input-method-name` + `button-confirm-start-recording`, (e) finalizes via `POST /api/recording/finalize {mode:'save'}` and asserts the language's named-URL store files (`appsettings.json` for C#, `.env` for Python / Node.js / Java) is byte-identical to the pre-flow snapshot (read via `GET /api/files`). ## JMX BFF classification

- `pnpm --filter @workspace/api-server exec vitest run src/features/jmx/infrastructure/__tests__/bffEndpointClassifier.test.ts`: Unit suite for the BFF endpoint classifier (`classifyBffEndpoint` + `classifyEventStream` in `artifacts/api-server/src/features/jmx/infrastructure/bffEndpointClassifier.ts`). Asserts the per-URL rules: same-origin-as-`targetUrl` is `bff`, cross-origin defaults to `upstream`, hosts already known as IdPs (or matching the OAuth/OIDC marker-path heuristic in `looksLikeIdpRequest`, e.g. `/.well-known/openid-configuration`, `/oauth2/authorize`, `/connect/token`) are `idp`, and malformed URLs / an empty `targetUrl` fall through to `upstream`. Also covers the session-aware sticky behavior of `classifyEventStream`: once a marker path promotes a host to IdP, every subsequent request to that host in the same stream inherits the `idp` class. Pure-function tests, no server / db / browser needed.
- `pnpm --filter @workspace/api-server exec vitest run src/features/jmx/infrastructure/__tests__/jmxIrBffGrouping.test.ts`: IR-shape snapshot suite for the JMX tree builder's BFF grouping pass (`buildJmxTree` in `artifacts/api-server/src/features/jmx/infrastructure/jmxIr.ts`). Asserts (a) `bff: false` (the default) leaves the existing flat sampler layout byte-identical to the pre-BFF shape, with no `[BFF]` / `[IdP]` / `[Upstream]` prefixes and no `GenericController` wrappers, so the feature is provably no-op for non-BFF projects; (b) `bff: true` wraps the samplers in up to three labelled `GenericController` nodes named **BFF**, **IdP**, and **Upstream API** in that fixed order and prefixes each sampler's `testname` with the matching `[BFF]` / `[IdP]` / `[Upstream]` tag; and (c) empty class buckets are omitted, so a session that never hit an IdP gets no empty "IdP" controller.
